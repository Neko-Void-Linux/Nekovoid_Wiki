# Wayland

Wayland is a modern communication protocol for Linux and Unix-like operating systems that defines how applications interact directly with the display server to render visuals on screen and process keyboard, mouse, and touch input.

Unlike the traditional X11 architecture, Wayland removes the independent display server intermediary. Applications render their graphical frames directly into shared memory buffers and communicate with the window manager (the compositor). The compositor acts as the unified display server, gathering all system buffers and drawing the final output to the monitor.

## Requirements

The vast majority of Wayland compositors require **Kernel Mode Setting (KMS)** support in the Linux kernel. Wayland itself does not provide a desktop environment; it requires an independent compositor or a desktop environment that includes its own compositor (such as KDE Plasma with KWin).

For the GPU driver and the Wayland compositor to communicate, both must support the same buffer API:

| Buffer API | GPU Driver Support | Wayland Compositor Support |
| :--- | :--- | :--- |
| **GBM** | Almost all (including NVIDIA ≥ 495) | Almost all |
| **EGLStreams** | Legacy NVIDIA | Limited (e.g. legacy GNOME) |

> [!NOTE] NVIDIA Support
> NVIDIA drivers version 495 and newer natively support the GBM buffer API.

### Checking Display Logs in Neko Void (runit)

Because Neko Void uses **runit** instead of systemd, the `journalctl` utility is not available. To inspect which renderer is currently active and review display errors, check your compositor's output in the TTY or inspect the session log generated by your display manager:

```bash
cat ~/.local/share/sddm/wayland-session.log
```

To force GBM as the global backend on NVIDIA systems, set the following environment variables in `/etc/environment` or your user profile (`~/.bash_profile` / `~/.profile`):

```bash
GBM_BACKEND=nvidia-drm
__GLX_VENDOR_LIBRARY_NAME=nvidia
```

## Available Compositors

In addition to full desktop environments like KDE Plasma, Neko Void offers first-class support for several standalone, lightweight compositors. Many of them use **Noctalia shell** as their default shell interface:

### Tiling Compositors

- **Niri**: A dynamic, scrollable-tiling Wayland compositor with endless horizontal layout workspace management.
- **MangoWM**: A lightweight, fast compositor with visual effects based on wlroots and scenefx.
- **Sway**: An i3-compatible tiling Wayland compositor built on top of wlroots.

### Stacking Compositors

- **LabWC**: A stacking window compositor based on wlroots, inspired by the speed and minimalist configuration of Openbox.

### Additional Options in Void Linux Repositories

The official Void Linux package repositories host a variety of alternative compositors:

- **SwayFX**: Sway fork featuring extra eye candy (drop shadows, rounded corners, blur).
- **River**: A dynamic, tag-based tiling compositor inspired by dwm and bspwm.
- **Cagebreak**: A tiling compositor based on cage, inspired by ratpoison.
- **Qtile**: A hackable, full-featured Python-configured tiling window manager and compositor (`qtile-wayland` package).
- **Wayfire**: A 3D compositor inspired by Compiz, delivering smooth animations and desktop effects.

## Display Managers

The following display managers available in Neko Void support launching Wayland sessions:

- **Emptty**: Ultra-lightweight TUI display manager with zero X11 dependencies.
- **LightDM**: Configurable display manager with Wayland session support.
- **SDDM**: Modern QML-based display manager, recommended for KDE Plasma and Qt setups.
- **GDM**: The official display manager of the GNOME project.
- **Greetd**: An extensible login daemon supporting diverse console and graphical frontends.

## Xwayland

**Xwayland** is a compatibility layer that enables legacy X11 applications and games to run seamlessly inside a modern Wayland session.

To enable Xwayland support, install the appropriate package:

```bash
# For most wlroots-based compositors and KDE:
xbps-install -S xorg-server-xwayland

# For Niri, the auxiliary satellite bridge is required:
xbps-install -S xwayland-satellite
```

> [!IMPORTANT] Xwayland Considerations
> - **Security**: Because it runs an in-memory X server, it does not provide the strict per-client isolation inherent to native Wayland.
> - **Performance**: Delivers near-native performance, though older NVIDIA setups may encounter quirks.
> - **Compatibility**: While it handles almost all standard GUI apps, some legacy X11 utilities that rely on global input hooks may require native Wayland alternatives.

### Identifying Xwayland Applications

You can determine whether a running window is operating under Xwayland using either of these utilities:

1. **Using `xeyes`**: Run `xeyes` in a terminal. If the eyes track your mouse pointer while hovering over an application window, that application is running under Xwayland.
2. **Using `xwininfo`**: Run `xwininfo` in a terminal. When hovering over an Xwayland window, the mouse cursor turns into a crosshair (`+`). Clicking the window displays its technical attributes.

## Tips & Tricks

### Automation Tools

- **`ydotool`**: Command-line automation tool for simulating keystrokes and mouse events across the system. Requires enabling the `ydotoold` runit service in `/var/service/` and adding your user account to the `input` group (`usermod -aG input <user>`).
- **`wtype`**: Keystroke simulator designed specifically for Wayland compositors that implement the virtual keyboard protocol.
- **Python Libraries (`keyboard`, `mouse`)**: Allow capturing and simulating input events directly from `/dev/input/` (requires root privileges or `input` group access).

### Key and Mouse Remapping

- **`input-remapper`**: GUI utility to remap buttons, keys, and macros with per-device configuration.
- **`xremap`**: Display-server-agnostic key remapper for Wayland featuring YAML configuration and per-application keybinding rules.

## Troubleshooting

### Remote Desktop & Streaming

- **`wayvnc`**: VNC server for wlroots-based compositors (such as Sway).
- **`krfb` & `krfb-virtualmonitor`**: VNC solution for KWin in KDE Plasma with support for adding virtual displays.
- **`waypipe`**: Transparent proxy for Wayland applications over SSH:

```bash
waypipe ssh user@server.local env QT_QPA_PLATFORM=wayland-egl dbus-launch kcalc
```

### Input Capture in Games & Virtual Machines

Unlike X11, Wayland prevents arbitrary applications from capturing input globally without permission. Modern compositors manage pointer locking and cursor confinement via dedicated protocol extensions (`pointer-constraints` and `relative-pointer`). Ensure these protocols are enabled in your compositor configuration.

### GTK Themes in Standalone Compositors

To configure and synchronize GTK themes, icons, and mouse cursors in standalone compositors without a full desktop settings daemon, install **`nwg-look`**:

```bash
xbps-install -S nwg-look
```

For further details, consult the [Sway GTK-3 settings on Wayland wiki guide](https://github.com/swaywm/sway/wiki/GTK-3-settings-on-Wayland).

### Blurry X11 Applications Under Fractional Scaling

When using fractional scaling on HiDPI displays, certain X11 applications may appear blurry due to bitmap scaling. This is tracked in the [xserver sharp scaling merge proposal](https://gitlab.freedesktop.org/xorg/xserver/-/work_items/1318).
